# Software factory v3

v3 = v2 + rework que funciona + permisos forzados + menos tokens. Mismo flujo y mismos comandos.

## Qué cambió

**Rework con feedback humano**
- Comentarios, reviews ("Request changes") y comentarios en línea del PR cuentan como feedback, solo del operador y de gente con permiso de escritura (OWNER/MEMBER/COLLABORATOR). `job queue` marca el job como `resume` ("feedback on PR #n").
- `/factory <texto>` sigue funcionando; las dos fuentes se juntan en `feedback-<k>.md`, citadas como dato.
- El feedback pasa por **spec**: el spec-writer agrega `## Changes from feedback <k>` y `### Decided by the human`. `job advance spec→build` se niega si falta.
- Revisores y approver leen el feedback; el approver no re-escala lo que el humano ya decidió.

**Tokens**
- intake: fable → sonnet.
- Ronda de rework: solo re-revisan los lentes que pidieron CHANGES, más `code` (`job reviewers <id>`). Tras feedback revisan todos.
- Los revisores arrancan por `git diff <commit revisado>..HEAD`.
- El approver lee la ronda final y la última review de cada lente, no todo el historial.

**Permisos**
- `factory/bin/guard`: hook PreToolUse en cada agente. Cada uno escribe solo su archivo (el builder, además, `.worktrees/`); solo el builder commitea y pushea, y solo a `factory/*`; nadie mergea, hace force push, `reset --hard`, `rm -rf` ni `sudo`.
- `.claude/settings.json`: los mismos deny para la sesión principal.
- Límite: un agente todavía puede escribir con una redirección de Bash. El guard frena errores y abusos obvios; el gate y las reviews siguen siendo el control real.

**Tests**: `python3 -m unittest discover factory/tests` (transiciones, feedback desde el PR, guard; `gh` simulado).

## Git Flow
Poné `"base_branch": "develop"` en `factory/config.json`: la fábrica mergea a `develop` y `develop → main` lo hacés vos.
